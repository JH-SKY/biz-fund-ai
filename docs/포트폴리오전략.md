🎨 비즈업(Biz-Up) 포트폴리오 페이지 구성 전략
전체 분량은 6~7페이지 내외로 압축하되, 각 페이지가 하나의 '기술적 증명'이 되도록 구성합니다.

[1페이지] 서비스 정의: "소상공인의 돈을 찾아주는 AI 에이전트"
핵심 가치: "복잡한 정부 지원금, 비즈업이 당신의 사업장을 분석해 매칭합니다."

문제 의식: "정보의 비대칭성으로 인해 소상공인이 매년 놓치는 정책 자금 00조 원."

해결 방안: AI 기반의 자동 사업장 진단 및 맞춤형 정책 매칭 시스템.

[2페이지] 서비스 아키텍처: "데이터가 흐르는 길을 설계하다"
기술 스택: FastAPI, SQLAlchemy 2.x, PostgreSQL(Supabase), Next.js.

데이터 흐름도: 제미나이가 정리해준 '데이터 흐름(3계층 구조)'을 도식화해서 넣습니다.

강조점: "Scalability(확장성)를 고려한 Repository-Service 패턴의 계층 구조 설계."

[3페이지] 필살기 ①: Hybrid RAG 파이프라인
핵심 기술: LangChain + pgvector + Hybrid Search.

디테일: 단순히 검색만 하는 게 아니라, 'Magic Number 탐지'와 '중첩 트랜잭션'을 통해 오염된 데이터 유입을 차단하는 '데이터 신뢰성 확보 로직'을 강조합니다. (이게 라이언님의 실무 역량 포인트입니다.)

[4페이지] 필살기 ②: AI Agent '비즈몽(BizMong)'
핵심 기술: LangGraph 기반 상태 관리형 챗봇.

차별화: 단순히 묻고 답하는 챗봇이 아니라, 사용자의 진단 결과와 현재 페이지 문맥을 읽고 다음 행동을 제안하는 '능동적 에이전트'임을 강조합니다. (Stateful Agent)

[5페이지] 운영 및 최적화: "지속 가능한 개발자"
모니터링: 레이턴시 차트(p95) 시계열 집계, 토큰 비용 추적 로직.

성능: Redis 캐싱을 통한 AI 응답 속도 개선 시도.

피드백 루프: 사용자의 피드백을 수집하여 정정 노트를 생성하고 모델 답변을 개선하는 구조.

[6페이지] 트러블슈팅: "어려움을 어떻게 극복했는가"
이슈: Supabase pgbouncer 호환성 문제 혹은 외부 API 데이터 오염 이슈.

해결: 어떤 사고 과정을 거쳐 문제를 정의하고, 기술적으로 어떻게 우회했는지 (05_troubleshooting_log.md 내용 활용).
