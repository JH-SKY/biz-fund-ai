# 📁 Side Project Documentation Guidelines

이 가이드라인은 프로젝트의 기획부터 설계, 트러블슈팅까지의 전 과정을 체계적으로 기록하기 위해 작성되었습니다. 각 파일은 프로젝트의 전문성을 보여주는 핵심 문서가 됩니다.

---

## 🏠 README.md (프로젝트 대문)
1. **프로젝트 타이틀 & 슬로건**: 한눈에 들어오는 이름과 서비스의 정체성.
2. **핵심 요약 (Introduction)**: 문제 해결 및 기획 배경 (2~3줄).
3. **핵심 기능 (Key Features)**: 사용자 중심 기능 3~4개 (아이콘 활용).
4. **기술 스택 (Tech Stack)**: 사용 언어, 프레임워크, DB 등.
5. **문서 바로가기 (Documentation)**: 01~04번 파일 링크 및 설명.
6. **버전 관리 (Changelog)**: v1.0, v1.1 등 주요 업데이트 요약.

---

## 📂 01_concept_and_requirements.md (기획 및 요구사항)
1. **기획 의도 (Why)**: 프로젝트 시작 동기 및 문제 정의.
2. **타겟 유저 (Persona)**: 서비스 대상 정의.
3. **핵심 기능 (Must-have)**: 필수 구현 기능 상세.
4. **확장 기능 (Nice-to-have)**: 추후 고도화 및 AI 에이전트 적용 계획.

---

## 🏗️ 02_system_architecture.md (시스템 아키텍처)
1. **아키텍처 다이어그램**: 시스템 구성 구조 설명.
2. **데이터 흐름 (Data Flow)**: 요청부터 응답까지의 이동 경로.
3. **인프라 구성**: Docker, 클라우드, 외부 API 연동 환경.

---

## 🔌 03_data_design_spec.md (API 및 DB 설계)
1. **API 명세 (API Spec)**: 엔드포인트, Method, Request/Response, 에러 코드.
2. **DB 스키마 (Database)**: ERD 설명, RDB(PostgreSQL) 및 Vector DB 테이블 명세.
3. **데이터 매핑**: API와 DB 간 데이터 변환 및 저장 전략.

---

## 🧪 04_experiment_and_test.md (실험 및 평가)
1. **프롬프트 실험**: 페르소나 설정 전후 결과 비교 등.
2. **모델 비교**: GPT, Claude 등 모델별 성능/비용 분석.
3. **성능 지표**: 답변 속도, 검색 정확도 등 정량적 테스트 결과.

---

## 🛠️ 05_troubleshooting_log.md (성장 기록)
1. **문제 상황**: 에러 메시지나 기술적 난관 요약.
2. **원인 분석**: 발생 이유에 대한 논리적 분석.
3. **해결 과정**: 시도한 방법들과 최종 해결 코드 및 설계.
4. **회고**: 재발 방지책 및 습득한 실무 지식.
