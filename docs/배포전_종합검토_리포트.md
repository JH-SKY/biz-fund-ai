## 1-2. CORSMiddleware 등록

### 문제 근거
```python
# backend/src/app/main.py 전체 (현재)
app = FastAPI(title="Biz-Fund-AI API", ...)
app.add_exception_handler(RequestValidationError, request_validation_exception_handler)
app.include_router(api_router)
```
- 어디에도 `CORSMiddleware` 등록이 없음.
- 로컬에서 Next.js `http://localhost:3000` → FastAPI `http://localhost:8000`은 Next.js 개발 서버가 proxy rewrites 설정이 없으면 preflight OPTIONS부터 차단됩니다.
- 프로덕션에서 프론트(`https://bizup.vercel.app`)와 백엔드(`https://api.bizup.com`)가 분리되는 순간 **전체 API가 막힙니다**.

### 구체 작업

**Step 1.** `backend/src/app/core/config.py`에 환경변수 추가
```python
# CORS 허용 도메인 (쉼표 구분). production에서는 실제 프론트 도메인만 허용.
CORS_ALLOW_ORIGINS: list[str] = [
    o.strip() for o in os.getenv(
        "CORS_ALLOW_ORIGINS",
        "http://localhost:3000,http://127.0.0.1:3000"
    ).split(",") if o.strip()
]
```

**Step 2.** `backend/src/app/main.py`에 미들웨어 추가
```python
from fastapi.middleware.cors import CORSMiddleware
from src.app.core.config import CORS_ALLOW_ORIGINS

app.add_middleware(
    CORSMiddleware,
    allow_origins=CORS_ALLOW_ORIGINS,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
    expose_headers=["X-Business-Id"],  # 프론트가 이 헤더를 읽지 않지만 확장성 대비
)
```

**Step 3.** `backend/.env`에 주석 포함 추가
```env
# 쉼표 구분. 로컬 개발은 localhost, 프로덕션은 https://bizup.vercel.app 등
CORS_ALLOW_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

### 검증
1. 서버 재시작 후 `curl -i -X OPTIONS http://localhost:8000/api/v1/policies -H "Origin: http://localhost:3000"` 실행.
2. 응답 헤더에 `access-control-allow-origin: http://localhost:3000` 포함되면 성공.

### 주의사항
- **`allow_origins=["*"]`로 열어두지 말 것.** `allow_credentials=True`와 함께 쓰면 FastAPI/starlette이 내부적으로 Origin을 반사하는데, 세션 탈취 위협이 커집니다.

## 1-3. `BaseAppException` 전역 핸들러 등록

### 문제 근거

정의부:
```python
# backend/src/app/core/exceptions.py 50~86
class BaseAppException(Exception):
    def __init__(self, status_code: int, message: str): ...
class ForbiddenException(BaseAppException): ...
class NotFoundException(BaseAppException): ...
class RateLimitException(BaseAppException): ...
class ServiceUnavailableException(BaseAppException): ...
```

사용처 예시:
```python
# backend/src/app/domains/diagnosis/service.py 8번째 줄
from src.app.core.exceptions import NotFoundException, ForbiddenException
...
raise NotFoundException("진단 기록을 찾을 수 없습니다.")
```

그러나 `main.py`에는 `RequestValidationError` 핸들러만 등록되어 있어, `NotFoundException`이 raise되면 FastAPI가 이를 **순수 Python `Exception`으로 취급**하여 `500 Internal Server Error`로 응답합니다. 의도한 `status_code`/`message`는 모두 사라집니다.

### 구체 작업

**Step 1.** `backend/src/app/core/exceptions.py` 하단에 핸들러 추가
```python
async def base_app_exception_handler(
    _request: Request,
    exc: BaseAppException,
) -> JSONResponse:
    """BaseAppException 계열을 공통 envelope 형식으로 응답."""
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "status": exc.status_code,
            "message": exc.message,
        },
    )
```

**Step 2.** `backend/src/app/main.py`에서 등록
```python
from src.app.core.exceptions import (
    BaseAppException,
    base_app_exception_handler,
    request_validation_exception_handler,
)

app.add_exception_handler(BaseAppException, base_app_exception_handler)
app.add_exception_handler(RequestValidationError, request_validation_exception_handler)
```

**Step 3 (선택, 강력 권장).** 최상위 catch-all도 추가하여 예기치 못한 예외가 500으로 나갈 때 envelope 형식은 유지
```python
from fastapi import HTTPException

@app.exception_handler(Exception)
async def unhandled_exception_handler(_request: Request, exc: Exception) -> JSONResponse:
    # HTTPException은 FastAPI 기본 처리 유지
    if isinstance(exc, HTTPException):
        raise exc
    logger.exception("Unhandled exception")
    return JSONResponse(
        status_code=500,
        content={"status": 500, "message": "서버 내부 오류가 발생했습니다."},
    )
```

### 검증
- 진단 상세 조회 시 존재하지 않는 UUID로 요청 → 응답 body가 `{"status": 404, "message": "진단 기록을 찾을 수 없습니다."}`여야 함.
- 현재는 `{"detail": "Internal Server Error"}`가 나오며 상태코드도 500입니다.

## 1-5. 프로덕션에서 기본 JWT Secret 사용 시 기동 실패

### 문제 근거
```python
# backend/src/app/core/config.py
ADMIN_JWT_SECRET: str = os.getenv("ADMIN_JWT_SECRET", "dev-admin-jwt-change-me")
USER_JWT_SECRET: str = os.getenv("USER_JWT_SECRET", "dev-user-jwt-change-me")
```

환경변수 주입을 깜빡해도 서버가 **모두가 아는 시크릿**으로 조용히 기동되어 토큰을 발급합니다. 해당 토큰은 누구나 위조 가능합니다.

### 구체 작업

`backend/src/app/core/config.py` 말미에 startup 가드 함수 추가:
```python
_DEFAULT_SECRETS = {
    "dev-admin-jwt-change-me",
    "dev-user-jwt-change-me",
}

def assert_production_secrets() -> None:
    """production 환경에서 기본/빈 시크릿이면 즉시 RuntimeError.

    main.py의 lifespan startup에서 호출한다. 서버가 절대 기동되지 않도록.
    """
    if APP_ENV != "production":
        return
    problems: list[str] = []
    if not ADMIN_JWT_SECRET or ADMIN_JWT_SECRET in _DEFAULT_SECRETS:
        problems.append("ADMIN_JWT_SECRET")
    if not USER_JWT_SECRET or USER_JWT_SECRET in _DEFAULT_SECRETS:
        problems.append("USER_JWT_SECRET")
    if not OPENAI_API_KEY:
        problems.append("OPENAI_API_KEY")
    if problems:
        raise RuntimeError(
            f"[FATAL] Missing/weak secrets in production: {', '.join(problems)}"
        )
```

`main.py` lifespan startup 직후 호출:
```python
from src.app.core.config import assert_production_secrets

@asynccontextmanager
async def lifespan(app: FastAPI):
    assert_production_secrets()   # ← 추가
    start_scheduler()
    yield
    shutdown_scheduler()
```

### 검증
- `APP_ENV=production` + 기본 시크릿 상태로 서버 시작 → `RuntimeError` 발생해 기동 실패해야 함.

## 2-1. `POST /auth/refresh` 엔드포인트 구현

### 문제 근거

프론트가 호출하는 URL:
```typescript
// frontend/src/lib/api-client.ts 97~101
const resp = await axios.post<ApiResponse<{ access_token: string }>>(
  `${BASE_URL}/auth/refresh`,
  { refresh_token: refresh },
  ...
);
```

백엔드 `auth_router.py` 엔드포인트 전체:
- `POST /auth/social-login`
- `POST /auth/test-login`
- `POST /auth/logout`
→ **`/auth/refresh` 없음**. 401 응답 → 프론트 `tokenStorage.clear()` 호출 → 자동 로그아웃.

### 구체 작업

**Step 1.** `backend/src/app/domains/auth/schema.py`에 요청/응답 스키마 추가
```python
class RefreshTokenRequest(BaseModel):
    refresh_token: str

class RefreshTokenResponseData(BaseModel):
    access_token: str
```

**Step 2.** `backend/src/app/domains/auth/service.py`에 메서드 추가
```python
async def refresh_access_token(self, *, refresh_token: str) -> RefreshTokenResponseData:
    """유효한 Refresh Token으로 새 Access Token 발급.

    - 만료·무효화된 토큰이면 401 raise.
    - 신선한 access 토큰만 발급 (refresh 자체는 회전하지 않음, MVP 정책).
      → 추후 Refresh Token Rotation 도입 시 새 refresh도 발급하도록 확장.
    """
    token_row = await self._repo.get_valid_token(refresh_token)
    if token_row is None:
        raise auth_unauthorized("유효하지 않은 리프레시 토큰입니다.")

    user = await self._repo.get_user_by_id(token_row.user_id)
    if user is None or not user.is_active:
        raise auth_unauthorized("탈퇴했거나 비활성 계정입니다.")

    new_access = create_user_access_token(user_id=user.id)
    return RefreshTokenResponseData(access_token=new_access)
```

**Step 3.** `backend/src/app/api/v1/auth_router.py`에 엔드포인트 추가
```python
from src.app.domains.auth.schema import RefreshTokenRequest

async def refresh_access_token(
    body: RefreshTokenRequest,
    svc: Annotated[AuthService, Depends(get_auth_service)],
):
```

### 검증
1. 로그인 → access, refresh 획득
2. access 토큰을 임의로 잘못된 값으로 바꿔 API 호출 → 401
3. 프론트 인터셉터가 `/auth/refresh` 호출 → 새 access 받아 원요청 재시도 → 성공

### 주의사항
- **Refresh Token Rotation**(재발급 시 refresh도 새걸로) 고도화는 Phase 2 이후. 지금은 access만 재발급.
- `get_valid_token`은 DB에서 `is_revoked=False`와 `expires_at > now`를 모두 체크하므로 안전합니다.

## 2-4. `biz_pick_router` Optional 인증 수정

### 문제 근거
```python
# backend/src/app/api/v1/biz_pick_router.py 19번째 줄
current_user: Annotated[Optional[CurrentUser], Depends(CurrentUser)] = None,
```
- `CurrentUser`는 `Annotated[User, Depends(get_current_user)]`라는 **타입 별칭**.
- `Depends(CurrentUser)`는 타입을 의존성으로 넘기는 잘못된 패턴 → FastAPI가 런타임 에러 또는 강제 401.
- 그리고 `get_current_user`는 토큰 없으면 `raise auth_unauthorized()` → **비로그인도 403/401**.

### 구체 작업

**Step 1.** `backend/src/app/api/deps/user_auth.py`에 Optional 버전 추가
```python
async def get_optional_current_user(
    cred: Annotated[HTTPAuthorizationCredentials | None, Depends(bearer_scheme)],
    db: Annotated[AsyncSession, Depends(get_db)],
) -> User | None:
    """토큰이 없거나 유효하지 않아도 None을 반환. 인증 실패를 raise하지 않는다."""
    if cred is None or not cred.credentials:
        return None
    try:
        payload = decode_user_access_token(cred.credentials)
    except jwt.PyJWTError:
        return None
    if payload.get("type") != "access":
        return None
    sub = payload.get("sub")
    if not sub:
        return None
    try:
        uid = uuid.UUID(str(sub))
    except ValueError:
        return None
    repo = AuthRepository(db)
    return await repo.get_user_by_id(uid)


OptionalCurrentUser = Annotated[User | None, Depends(get_optional_current_user)]
```

## 2-6. Zustand persist hydration 경쟁 해결

- Zustand `persist` middleware는 **클라이언트 mount 후**에 localStorage를 읽어 상태를 복구합니다.

### 구체 작업

**Step 1.** `frontend/src/stores/auth-store.ts`에 hasHydrated 플래그 추가
```typescript
interface AuthState {
  ...
  hasHydrated: boolean;
  setHasHydrated: (v: boolean) => void;
}

export const useAuthStore = create<AuthState>()(
  persist(
    (set, get) => ({
      ...
      hasHydrated: false,
      setHasHydrated: (v) => set({ hasHydrated: v }),
    }),
    {
      name: "biz_up_auth",
      storage: createJSONStorage(safeStorage),
      onRehydrateStorage: () => (state) => {
        state?.setHasHydrated(true);
      },
    }
  )
);
```

```python
class OpenAILLMEngine(ILLMEngine):
    """OpenAI GPT-4o-mini 기반 실구현."""

    def __init__(self, api_key: str, model: str = "gpt-4o-mini") -> None:
        from openai import AsyncOpenAI
        self._client = AsyncOpenAI(api_key=api_key)
        self._model = model

    async def generate_reply(
        self,
        session_id: str,
        user_message: str,
        business_context: Dict[str, Any],
    ) -> LLMResponse:
        system_prompt = (
            "당신은 대한민국 중소기업·소상공인 정책자금 상담 전문가 '비즈몽'입니다. "
            "친근하고 간결한 한국어로, 존댓말과 '사장님' 호칭을 사용하여 답변합니다. "
            f"사업장 정보: 업종={business_context.get('sector')}, "
            f"상호명={business_context.get('biz_name')}, "
            f"프로필 점수={business_context.get('score')}"
        )
        try:
            resp = await self._client.chat.completions.create(
                model=self._model,
                messages=[
                    {"role": "system", "content": system_prompt},
                    {"role": "user", "content": user_message},
                ],
                temperature=0.3,
            )
            content = resp.choices[0].message.content or ""
            usage = resp.usage
            # gpt-4o-mini 기준 대략 비용 계산 (2026-04 시점 가격 기준, 확인 필요)
            cost = (
                (usage.prompt_tokens / 1_000_000) * 0.15 +
                (usage.completion_tokens / 1_000_000) * 0.60
            ) if usage else 0.0
            return LLMResponse(
                content=content.strip(),
                referenced_policy_ids=[],
                trace_id=resp.id,
                total_cost=cost,
            )
        except Exception as exc:
            import logging
            logging.getLogger(__name__).exception("OpenAI generate_reply 실패")
            return LLMResponse(
                content="죄송해요, 답변 생성 중 문제가 발생했어요. 잠시 후 다시 시도해 주세요.",
                referenced_policy_ids=[],
                trace_id=f"error-{session_id}",
                total_cost=0.0,
            )

    async def summarize_title(self, messages: List[str]) -> str:
        try:
            resp = await self._client.chat.completions.create(
                model=self._model,
                messages=[
                    {"role": "system", "content": "다음 대화를 15자 이내 한국어 제목으로 요약:"},
                    {"role": "user", "content": "\n".join(messages)},
                ],
                temperature=0.0,
            )
            return (resp.choices[0].message.content or "상담").strip()[:30]
        except Exception:
            return "상담"
```

```python
class RuleBasedDiagnosisEngine(IDiagnosisEngine):
    """규칙 기반 점수 + LLM 코멘트 생성.

    Phase 1 수준. 추후 AI 모델(LightGBM/XGBoost 등)로 교체.
    """

    def __init__(self, api_key: str | None, model: str = "gpt-4o-mini") -> None:
        self._model = model
        self._client = None
        if api_key:
            from openai import AsyncOpenAI
            self._client = AsyncOpenAI(api_key=api_key)

    async def execute_diagnosis(
        self, business: Business, year: int,
        inputs: Dict[str, Any], use_ai: bool = True,
    ) -> DiagnosisResult:
        # 1. 룰 기반 점수
        revenue = float(inputs.get("revenue", 0))
        employees = int(inputs.get("employee_count", 0))
        debt_ratio = float(inputs.get("debt_ratio", 100))

        stability = max(0, 100 - debt_ratio)                 # 부채비율 낮을수록 ↑
        growth = min(100, (revenue / 1_000_000_000) * 10)    # 10억당 10점
        tech = 50 + (20 if inputs.get("has_patent") else 0)
        total = round((stability * 0.4 + growth * 0.4 + tech * 0.2), 2)
        grade = "EXCELLENT" if total >= 80 else "GOOD" if total >= 60 else "NORMAL" if total >= 40 else "RISK"

        # 2. LLM 코멘트 생성 (optional)
        comment = ""
        if use_ai and self._client:
            try:
                resp = await self._client.chat.completions.create(
                    model=self._model,
                    messages=[
                        {"role": "system", "content": "정책자금 진단 결과 코멘트를 한국어로 2~3문장, 존댓말로 작성"},
                        {"role": "user", "content": f"총점 {total}, 안정성 {stability}, 성장성 {growth}, 기술성 {tech}"},
                    ],
                    temperature=0.4,
                )
                comment = (resp.choices[0].message.content or "").strip()
            except Exception:
                comment = "입력하신 재무지표 기준 건전한 상태입니다."

        return DiagnosisResult(
            total_score=total, grade=grade,
            scores={"stability": stability, "growth": growth, "tech": tech},
            ai_comment=comment,
        )

    async def execute_simulation(self, business, policy, conditions):
        # 가산점 시뮬레이션: conditions 플래그에 따라 가산
        base = 65.0
        gain = 0.0
        factors: list[str] = []
        if conditions.get("add_new_hire"):
            gain += 15; factors.append("신규 고용 가점 +15점")
        if conditions.get("has_patent"):
            gain += 8.5; factors.append("특허 보유 가점 +8.5점")
        if conditions.get("women_owned"):
            gain += 5; factors.append("여성기업 가점 +5점")
        return SimulationResult(
            base_rate=base, simulated_rate=min(100, base + gain),
            gain_factors=factors or ["변경된 조건 없음"],
        )
```

## 5-1. APScheduler 단일 인스턴스 가드

### 문제

**방안 A (간단, 권장)**: 전용 환경변수 가드

**방안 B (고급)**: PostgreSQL advisory lock

```python
async def _daily_policy_sync_job():

            ...
```

```python
def client_ip_from_request(request) -> str | None:
    """X-Forwarded-For 우선, 없으면 request.client.host."""
    xff = request.headers.get("x-forwarded-for")
```

# Batch 6 — 인프라 & CI/CD

> **목표**
> 신규 개발자가 `git clone` 후 **5분 안에 로컬 서버를 띄울 수 있게** 하고, 모든 PR에 대해 테스트/린트가 자동 실행되도록 합니다.

**예상 공수**: 1.5 일
**담당 영역**: DevOps 또는 백엔드 1인
**PR 제목 예시**: `chore(infra): docker-compose + GitHub Actions CI`
**의존**: Batch 1~5 선행 권장 (테스트 대상이 어느 정도 완성돼야 의미 있음)

## 포함 이슈

1. **`docker-compose.yml`이 비어 있음 (Q1)**
2. **`.github/` 비어 있음, CI 없음 (Q2)**
3. **`tests/` 비어 있음 (Q3)**

## 6-1. docker-compose.yml 작성

```yaml
# docker-compose.yml
version: "3.9"

services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: biz-fund-ai-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: biz_up
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-1234}
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d biz_up"]
      interval: 5s
      timeout: 5s
      retries: 5

  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: biz-fund-ai-backend
    env_file:
      - backend/.env
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "8000:8000"
    volumes:
      - ./backend:/app

volumes:
  postgres_data:
```

```dockerfile
FROM python:3.12-slim
```

# Batch 7 — 문서/품질 최종 정리

> **목표**
> 신규 개발자 온보딩과 운영 감사를 위해 **문서-구현-테스트가 모두 일치**하는 상태로 만듭니다.

**예상 공수**: 1 일
**담당 영역**: 전원
**PR 제목 예시**: `docs: align api spec with implementation + cleanup TODO`

## 포함 이슈

4. **DI 순환 의존 slim화 (Q8)**
5. **빈 문서 채우기 (Q10)**

## 7-1. API 명세서 전수 재작성

대상 파일:
- `docs/api_spec/auth.md` → `/auth/social-login`, `/auth/refresh`, `/auth/logout` 기준으로
- `docs/api_spec/chat.md` → `/chats/...` prefix로
- `docs/api_spec/biz_pick.md` → `/contents/...` prefix로
- 각 파일마다 응답 envelope(`{status, data, message}`) 예시 통일

## 7-2. 프론트 TODO 일괄 정리

검색 명령:
```bash
cd frontend
grep -rn "TODO\|FIXME" src/
```

처리 원칙:
- **Phase 1 범위**: 실제 구현으로 교체 (소셜 로그인, 온보딩 — 이미 Batch 2, 3에서 처리)
- **Phase 2로 미룸**: 이슈 번호 달아 GitHub Issue 등록 후 주석에 `TODO(#42): ...` 형태로 남김
- **불필요**: 제거

주요 파일:
- `frontend/src/features/landing/QuickMatchModal.tsx`의 `estimateSummary()` → 실제 API `/policies/summary?region=&industry=` 신설 후 교체 (Phase 2 이슈로 등록)
- `frontend/src/app/page.tsx`의 "로그인 세션 확인 TODO" → Batch 2의 hydration 처리로 교체
- `frontend/src/components/dashboard/BenefitLevelCard.tsx`의 `/businesses/{id}/benefit-level` → Phase 2 이슈로

## 7-3. 의존성 버전 재점검

`backend/pyproject.toml`의 이상 버전 조사:
- `langchain>=1.2.13` → 실재하지 않음. `langchain>=0.3.0` 또는 `langgraph`만 쓸 거면 langchain 자체 제거 검토.
- `openai>=2.29.0` → `openai>=1.55.0`
- `pytest>=9.0.2` → `pytest>=8.3.0`
- `sqlalchemy>=2.0.48` → `sqlalchemy>=2.0.30`

수정 후:
```bash
cd backend
rm uv.lock
uv sync
uv run pytest   # 회귀 확인
```
