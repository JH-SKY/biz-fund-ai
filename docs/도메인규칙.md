# 📘 비즈업(Biz-Up) 도메인 규칙서 (Domain Rules v2.2)

## 0. 핵심 원칙
- **Business-Centric:** 모든 판단은 "사용자"가 아닌 "사업장(Business)" 기준으로 수행한다.
- **Data Persistence:** Soft Delete를 원칙으로 하되, 법적 보존 기간이 만료된 개인정보는 물리 삭제한다.
- **Async First:** 데이터 연동 및 매칭 계산 등 무거운 로직은 비동기로 처리한다.

---

## 1. 사용자(User) 및 인증 규칙

### 1.1 회원가입 및 로그인
- 소셜 식별자(`social_id` + `social_provider`)를 유니크 키로 사용한다.
- **최초 로그인:** 회원가입 처리 후 온보딩 페이지로 강제 리다이렉트한다.
- **재방문:** 기존 사업장 존재 여부를 확인하여 대시보드 또는 사업장 등록 페이지로 이동시킨다.

### 1.2 탈퇴 및 상태 변경 (Retention & Isolation)
- 유저 탈퇴 시 `users.status = 'DELETED'` 및 `is_active = false` 처리한다.
- **Cascade 비활성화:** 유저 비활성화 시 소유한 모든 `businesses`도 자동으로 `is_active = false` 처리한다.
- **조회 격리:** 탈퇴 유저 및 관련 데이터는 일반 서비스 API 조회 결과에서 즉시 제외(Global Filter)한다.
- **법적 파기:** 탈퇴 데이터는 관련 법령(상법 등)에 따라 최대 5년 보관 후 **물리 삭제(Hard Delete)**한다.

---

## 2. 온보딩 및 사업장(Business) 규칙

### 2.1 사업자 정보 자동 연동
- 사업자번호 입력 시 국세청 API 등을 통해 업종, 주소, 개업일을 자동 수집한다.
- **Fallback:** 외부 API 호출 실패 시 사용자가 직접 입력할 수 있는 수동 모드(`is_manual = true`)를 제공한다.

### 2.2 1:N 구조 관리
- 1명의 사용자는 여러 개의 사업장을 가질 수 있다.
- **Context Lock:** 모든 정책 관련 API 요청 시 헤더 또는 쿼리에 `X-Business-Id`를 포함하여, 해당 사업장의 데이터만 조회/계산한다.

---

## 3. 재무 데이터 및 증빙 규칙

### 3.1 데이터 신뢰 등급 (Trust Level)
매칭 계산 시 데이터 출처(`source`)에 따라 다음 순서로 신뢰도를 부여한다:
1. **is_verified = true:** 전문가 또는 시스템에 의해 검증된 데이터
2. **source = 'USER':** 사용자가 직접 입력한 최신 결산 데이터
3. **source = 'GOV_API':** 공공기관 API를 통해 수집된 데이터
4. **source = 'AI':** 비즈몽(AI) 상담을 통해 추정/수집된 데이터

---

## 4. 정책 매칭 및 신호등 로직 (핵심)

### 4.1 매칭 엔진 프로세스
매칭은 반드시 아래 2단계 프로세스를 거친다.

**Step 1: 1차 필터 (Hard Filter)**
- 아래 조건 중 하나라도 해당 시 즉시 **RED(불가)** 판정:
  - 세금 체납 존재
  - 지원 제외 업종 (유흥, 사행성 등)
  - 지역/업력 등 필수 요건 미충족

**Step 2: 2차 점수 계산 (Scoring)**
- 필터 통과 시 가산점을 합산한다 (특허, 여성기업, 수출기업 등).
- **GREEN:** 필수 요건 충족 + 가산점 3점 이상
- **YELLOW:** 필수 요건 충족 + 가산점 0~2점
- **RED:** 필수 요건 미충족

### 4.2 매칭 결과의 불변성 (Snapshot)
- 모든 매칭 결과는 생성 시점의 사업장 데이터 **스냅샷(Snapshot)**을 함께 저장한다.
- 원본 데이터가 수정되어도 과거의 리포트 결과는 변하지 않아야 하며, 변경된 데이터로 '재계산' 시에만 신규 리포트를 생성한다.

### 4.3 매칭 트리거
- 사업장 정보 수정, 신규 재무 데이터 업로드, 또는 신규 정책 등록 시 매칭 로직을 재실행한다.

---

## 5. AI 상담 (비즈몽) 및 채팅 규칙

### 5.1 데이터 수집형 상담
- AI는 단순 답변을 넘어 사용자의 부족한 데이터(부채, 특허 유무 등)를 물어보고 이를 DB에 반영하는 역할을 수행한다.
- 수집된 정보는 `source = 'AI'` 태그와 함께 `pending_profile`에 저장 후 사용자의 최종 승인을 거쳐 반영한다.

### 5.2 채팅 세션 관리
- 1개의 사업장 당 여러 채팅방을 가질 수 있으나, '진행 중'인 상담은 하나만 유지한다.
- 7일간 응답이 없는 상담은 자동으로 `CLOSED` 상태로 변경한다.

---

## 6. 알림 및 관리 규칙

### 6.1 알림 발생(Push/In-app)
- **우선순위:** 매칭 상태가 RED에서 GREEN으로 변했을 때 가장 높은 우선순위로 알림을 발송한다.
- **마감 알림:** 관심 등록한 정책의 마감 3일 전 자동 알림을 생성한다.
- **탈퇴 유저 제한:** `is_active = false`인 유저에게는 어떠한 알림도 발송하지 않는다.

### 6.2 관리자 감사(Audit)
- 관리자의 모든 정책 수정 및 사용자 데이터 접근은 `audit_logs` 테이블에 기록되어야 한다.
- 특히 매칭 로직(가중치) 변경 시 변경 전/후 스냅샷을 저장한다.
