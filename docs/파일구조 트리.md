# 🏗️ [Biz-Fund-AI] 프로젝트 폴더 구조

## 1. 개요

본 문서는 **Biz-Fund-AI(비즈업)** 프로젝트의 전체 디렉토리 구조와 각 파일의 역할을 정의합니다.  
백엔드는 **router → service → repository → database** 4계층 흐름과 **도메인 중심 구조**를 엄격히 따릅니다.

### 5-3. src/app/ — 애플리케이션 핵심

```text
backend/src/app/
├── main.py                   # FastAPI 앱 인스턴스 생성 + 모든 도메인 모델 선행 로드, 라우터 마운트, 헬스체크 엔드포인트
│
├── core/                     # ⚙️ 전역 설정 및 인증 유틸│
├── database/                 # 🗄️ DB 연결 관리
│   └── postgres/
│       ├── database.py       # 비동기 SQLAlchemy 엔진·세션 생성, get_db() DI 함수
│       └── base.py           # DeclarativeBase 정의 (순수 Base 클래스 — 모델 import 없음)
│
├── domains/                  # 💼 도메인별 비즈니스 로직 + SQLAlchemy 모델
│   │                         #    각 도메인은 model / exception / schema / repository / service 세트
│   ├── auth/                 # [인증·사용자·관리자] 소셜 로그인, 로그아웃, 탈퇴, 관리자 계정
│   ├── admin/                # [관리자] 정책 등록·수정, 콘텐츠 관리, 통계, 감사 로그
│   ├── business/             # [사업장] 사업장 정보 등록·수정, 재무 스냅샷, 서류
│   ├── policy/               # [정책·비즈픽] 정책 공고 마스터, 비즈픽 콘텐츠
│   ├── diagnosis/            # [진단] 사업장↔정책 매칭 판정, 가산점 시뮬레이션
│   ├── chat/                 # [AI 상담] 비즈몽 채팅룸, 메시지 이력
│   ├── notification/         # [알림] 사용자 알림 발송 이력
│   └── system/               # [시스템] 파트너 상담 리드, 배치 작업 이력
│
└── api/                      # 🚪 외부 진입 계층 (Router + 의존성 주입)
    ├── deps/                 # FastAPI Depends() 의존성 모음
    └── v1/                   # API 버전 v1 라우터 세트
        ├── router.py         # v1 전체 라우터 집계 (auth / users / admin 통합)
        ├── auth_router.py    # POST /auth/kakao, /auth/naver, /auth/logout
        ├── users_router.py   # GET /users/me, PATCH /users/profile, DELETE /users/withdraw
        └── admin_router.py   # /admin/* 전체 관리자 API (11개 엔드포인트)
```

## 6. 전체 API 엔드포인트 현황

| 분류 | Method | Endpoint | 설명 |
|------|--------|----------|------|
| **인증** | POST | `/api/v1/auth/kakao` | 카카오 소셜 로그인/가입 |
| **인증** | POST | `/api/v1/auth/naver` | 네이버 소셜 로그인/가입 |
| **인증** | POST | `/api/v1/auth/logout` | Refresh Token 무효화 로그아웃 |
| **사용자** | GET | `/api/v1/users/me` | 내 프로필 조회 |
| **사용자** | PATCH | `/api/v1/users/profile` | 추가 프로필 설정 (관심분야 등) |
| **사용자** | DELETE | `/api/v1/users/withdraw` | 회원 탈퇴 (Soft Delete) |
| **관리자** | POST | `/api/v1/admin/login` | 관리자 토큰 발급 |
| **관리자** | POST | `/api/v1/admin/policies` | 신규 정책 공고 등록 |
| **관리자** | PATCH | `/api/v1/admin/policies/{id}` | 정책 공고 수정 |
| **관리자** | POST | `/api/v1/admin/contents` | 비즈픽 콘텐츠 발행 |
| **관리자** | PATCH | `/api/v1/admin/contents/{id}` | 비즈픽 콘텐츠 수정·비공개 |
| **관리자** | GET | `/api/v1/admin/chats/logs` | AI 상담 모니터링 로그 조회 |
| **관리자** | GET | `/api/v1/admin/stats/dashboard` | 운영 대시보드 통계 |
| **관리자** | GET | `/api/v1/admin/audit-logs` | 관리자 감사 로그 조회 |

## 7. 아키텍처 핵심 원칙 요약

```
[Client]
    │  HTTP Request
    ▼
[api/v1/*_router.py]        ← 요청 수신·응답 반환만 담당, 로직 없음
    │  Depends()
    ▼
[api/deps/*_auth.py]        ← JWT 검증, 현재 사용자/관리자 추출
    │
    ▼
[domains/*/service.py]      ← 비즈니스 로직, 트랜잭션 관리, 외부 API 호출
    │
    ▼
[domains/*/repository.py]   ← DB 접근 전용, CRUD·필터 쿼리만 수행
    │
    ▼
[domains/*/model.py]        ← SQLAlchemy ORM (DB 테이블 구조, 도메인 내 통합 관리)
    │
    ▼
[database/postgres/base.py] ← DeclarativeBase + 전체 모델 일괄 등록 (Alembic 인식)
    │
    ▼
[PostgreSQL]
```

> **금지 사항**: Router에서 DB 직접 접근 ❌ | Service에서 ORM 직접 조작 ❌ | Repository에서 비즈니스 판단 ❌
