# 01. 기획 및 요구사항 정의서

> **문서 목적**: Biz-Up 서비스의 배경, 사용자 여정, 비즈니스 요구사항과  
> 각 기능의 기술적 해결책을 논리적으로 연결하는 기획 문서.

---

## 1. 프로젝트 개요

- **서비스명**: Biz-Up (비즈업)
- **프로젝트명**: biz-fund-ai
- **AI 상담 기능명**: 비즈몽 (BizMong)
- **핵심 슬로건**: "사장님의 꿈(Mong)을 데이터로 현실화하는 AI 파트너"

### 기획 배경

| 문제 | 규모 | Biz-Up의 접근 |
|:---|:---|:---|
| 정보의 비대칭 | 연간 20조 원 정책자금 중 소상공인 80% 이상이 혜택 소외 | AI가 공고를 분석해 쉬운 일상 언어로 정책문서 재해석 |
| 실패 비용 낭비 | 부적격 공고 신청으로 낭비되는 시간과 행정력 | 규칙 기반 Hard Filter로 사전 제거 |
| 개선 방향 부재 | "안 된다"는 결과만 있고 "어떻게 해야 되는지" 없음 | 시뮬레이션으로 구체적 액션 플랜 제시 |
| 정보 접근 장벽 | 수십 페이지 공고문을 읽을 시간 없음 | AI 3줄 요약 + 카드 뉴스 형태 큐레이션 |

## 2. 타겟 사용자 (Persona)

### Primary: 정책자금 최초 신청 소상공인

- **상황**: 직원 2~3명 규모의 카페·식당·소매업, 창업 2~5년차
- **니즈**: "어떤 지원금을 받을 수 있는지" 처음부터 알고 싶다
- **페인포인트**: 공고를 찾아봐도 조건 해당 여부 불명확, 서류 준비하다 지쳐서 포기
- **Biz-Up이 주는 가치**: 사업장 정보 등록만 하면 맞는 정책 순위 리스트 + 이유 제공

### Secondary: 전략적 개선을 원하는 소상공인

- **상황**: 이미 정책자금 신청 경험 있음, 이번엔 더 유리한 조건으로 받고 싶음
- **니즈**: "특허를 취득하면 얼마나 유리해지는지" 구체적으로 알고 싶다
- **Biz-Up이 주는 가치**: 시뮬레이션으로 투자 대비 정책자금 수혜 가능성 변화를 정량화

## 3. 5단계 사용자 여정 (User Journey)

### [1단계] 비즈-온 (Biz-On): 데이터 기반 스마트 온보딩

**목표**: 사장님이 직접 타이핑하는 수고를 70% 이상 줄여 초기 신뢰 확보.

- **자동 데이터 연동 (Zero-Input)**
  - 사업자등록번호 하나로 **국세청 API** 연동 → 개업일, 주소, 업종(KSIC), 법인 여부 자동 식별
  - `Business.is_biz_no_verified`, `biz_verified_status`, `tax_type` 필드로 인증 상태 관리

- **프로필 정교화**
  - 상시 근로자 수 입력 (4대 보험 가입 기준 설명 제공)
  - 군필 여부: 성별 데이터 기반 동적 노출 (남성일 경우에만)
  - 특수 가점 항목: 여성기업(`is_female_ent`), 벤처기업(`is_ventured`), 특허 보유(`has_patent`) 버튼형 수집

---

### [2단계] 비즈체크 (Biz-Check): 1:1 정밀 진단 매칭

**목표**: 막연한 정보 제공이 아니라 **"지금 [노란불]이니 부채비율을 10%만 낮추면 [초록불]"** 같은 액션 플랜 제시.

**[비즈몽 AI 에이전트]**

| 에이전트 | 설명 |
|:---|:---|
| 정밀진단 (diagnosis) | Hard Filter(규칙) + LLM Evaluator(Batch 채점) → 100점 스코어카드 + 상위 10개 정책 |
| 시뮬레이션 (simulator) | 가상 변수 적용 → 점수 변화 + Grant ROI 계산 |
| RAG 검색 (rag) | Hybrid RAG (pgvector + FTS + RRF) → 특정 정책 Q&A |
| 통계 비교 (stats) | DB 집계 → 동종업계 백분위 비교 |

**[채점 기준]**:

| 분류 | 항목 | 배점 | 세부 산정 로직 |
| :--- | :--- | :--- | :--- |
| **혁신성 (30)** | **기술 및 인증** | 30 | 벤처인증(+15), 특허등록(+10), 기업부설연구소(+5) |
| **고용 (25)** | **일자리 창출** | 25 | 10인 이상(25), 5~9인(15), 1~4인(10) / 최근 6개월 내 신규채용 시(+5 가점) |
| **안정성 (25)** | **재무 건전성** | 25 | 매출 10억+(25), 5억+(15), 1억+(5) / 부채비율 200% 이하 유지 시(+5 가점) |
| **지속성 (20)** | **사업 역량** | 20 | 업력 7년 이상(20), 3~7년(15), 3년 미만(10) / 대표자 동종업계 경력 5년+(+5 가점) |
| **감점 요소** | **리스크 관리** | - | 부채비율 200% 초과 (-10), 최근 1년내 연체 이력 (-20) |

**[신호등 판정]**:
- 🔴 **빨강 (부적격)**: 하나라도 해당 시 즉시 탈락
  - 국세 및 지방세 체납 중 (완납 증명 불가)
  - 정책자금 지원 제외 업종 (유흥, 도박, 사행성, 전문직 등)
  - 자본잠식 (자기자본 전액 잠식)
  - 최근 6개월 이내 연체 기록 보유

- 🟡 **노랑 (보완 필요)**: 자격은 되나 승인율이 낮음
  - 부채비율 200% 초과 (업종 평균 대비 높음)
  - 최근 1년 이내 정책자금 수혜 이력 있음 (중복 지원 제한)
  - 매출액이 전년 대비 30% 이상 급감

- 🟢 **초록 (적격)**: 승인 가능성 높음
  - 필수 요건 모두 충족 및 체납 없음
  - 업력 3년 이상 또는 정부 지원 사업 선정 이력 보유

### [3단계] 경영 최적화 (Business Optimization): 실전형 비용 절감 시뮬레이션

**목표**: 빌리는 돈만 신경 쓰는 게 아니라, **안 나갈 돈(비용 절감)**과 **더 받을 수 있는 자격(가점)**을 동시에 챙겨주는 독보적 가치 제공.

**자금 조달 시뮬레이션 (Funding Simulator)**
- 특정 정책자금 수령 시 월별 상환액 및 이자 부담액 자동 계산
- 고금리 시중 대출을 정책자금으로 **대환(Refinancing)** 시 연간 순이자 절감액 가시화
  - 예: 시중 5.0% → 정책 3.0% 대환 시, 1억 원 3년 만기 기준 절감액 ≈ **320만 원**

**인프라 도입 ROI (Smart Infra)**
- 서빙 로봇·키오스크 도입 시 인건비 대비 투자 회수 기간 산출
$$ROI(회수\ 개월) = \frac{기기\ 도입\ 자부담금}{월간\ 절감\ 인건비 - 월간\ 기기\ 유지비}$$
- **바우처 연계**: '스마트 상점 기술보급사업' 등 즉시 신청 가능한 정부 바우처 매칭 → 실제 자부담금 경감

**가점 빌드업 (Build-up Strategy)**
- "직원을 1명 채용할 경우", "특허/실용신안 취득할 경우" 변화하는 합격 확률 시뮬레이션

---

### [4단계] 비즈-벤치마크 (Biz-Benchmark): 동종업계 데이터 기반 비교

**목표**: 막연한 정보보다 **동종업계의 실제 수치**를 보여줌으로써 정책자금 신청 실행력 극대화.

- **합격자 프로필 대조**: "사장님과 비슷한 조건 사장님들이 가장 많이 선정된 자금 TOP 3" 노출
- **평균 수혜 금액 시각화**: 해당 공고의 평균 선정 금액 vs 사장님 예상 신청 가능 금액 비교
- **백분위 비교**: 동종업계(ksic_code 기준) 매출·인원·부채비율 상위 % 표시

**기술 구현** (외부 API 없음, 인프라 비용 0원):
```
- business_financial_snapshots 테이블 동종업계 집계
- 최소 5개 사업장 데이터 확보 시 업종 비교, 미달 시 전국 평균 폴백
- 백분위: 평균 대비 3배+ → 상위 10%, 2배+ → 상위 25%, 이상 → 상위 50%
```

---

### [5단계] 사후 관리 (Retention & Support): 지속 가능한 파트너십

**비즈-히스토리 (Timeline)**
- 상담 내역, 지원 이력, 결과를 타임라인으로 관리 → '나만의 경영 실무 일지'
- `chat_rooms`, `chat_logs`, `applications` 테이블 기반

**비즈-핑 (Smart Notification)**
- 관심 정책(`policy_bookmarks`) 마감 임박 알림
- 업력 증가로 새로운 자격 충족 시 신규 정책 푸시
- 3개월 주기 경영 데이터 업데이트 유도
- `Notification` 모델 + 알림 설정 컬럼 기반 인프라 준비 완료

**서류 보관함 (Document Vault)**
- 사업자등록증, 부가세증명원 등 필수 서류 업로드
- **OCR 자동 분석**: 서류에서 재무 수치 자동 추출 → 사업장 프로필에 반영
- `Document.ocr_status`, `ocr_result` + `BusinessFinancialSnapshot.ai_analysis_report`

## 4. 비AI 기능 요구사항

### 4.1 비즈-픽 (Biz-Pick) 콘텐츠 큐레이션

**데이터 수집 파이프라인**:
1. **수집**: 매일 오전 09:00 외부 API(기업마당, K-Startup 등)에서 신규 공고 수집
2. **구조화**: GPT-4o가 공고문 분석 → `target_logic`, `bonus_logic`, `ai_summary` 생성
3. **AI 요약**: "이 사업은 [매출 1억 미만] 사장님께 딱입니다. [서류 3장]만 있으면 됩니다!" 형태로 가공
4. **매칭**: 사용자 업종·지역 태그와 대조하여 개인화 우선순위 배치

**`biz_pick_policies` 테이블 기반**: 정책과 콘텐츠 간 N:M 관계 처리.

### 4.2 서류 OCR 자동화

- 사업자등록증 업로드 → OCR → `Business` 프로필 자동 채움
- `Document.ocr_status`: PENDING → COMPLETED (비동기 처리)
- 추출된 재무 수치는 `BusinessFinancialSnapshot.ai_analysis_report`에 저장

### 4.3 국세청 API 연동 (온보딩)

- `POST /onboarding/verify-biz`: 사업자번호 → 국세청 API → 사업자 상태 확인
- `Business.is_biz_no_verified = True` 설정 → 재호출 불필요 (캐싱)
- 반환 데이터: `biz_verified_status`(계속사업자/휴업자/폐업자), `tax_type`(과세 유형)

### 4.4 알림 시스템

- **발송 조건**: 정책 마감 임박(D-7, D-3, D-1), 업력 기준 충족, 신규 맞춤 공고
- **채널**: 서비스 내 알림 목록 (`/notifications`)
- `Notification` 모델 + 사용자별 알림 설정 컬럼으로 구현

## 5. 데이터 수집 출처

| 분류 | 출처 | 수집 데이터 |
|:---|:---|:---|
| 정책 공고 | 기업마당, K-Startup, 각 지자체 | 공고명, 지원 조건, 지원금액, 마감일 |
| 사업자 인증 | 국세청 사업자등록 진위확인 API | 개업일, 업종(KSIC), 사업자 상태, 과세 유형 |
| 재무 데이터 | 사용자 직접 입력 / 서류 OCR | 매출, 부채, 직원수, 체납 여부 |
| 동종업계 통계 | 서비스 내 누적 데이터 | 업종별 평균 매출·인원·부채비율 |

## 6. 비즈니스 가치 및 확장 방향

| 이해관계자 | 비즈니스 가치 |
|:---|:---|
| **소상공인 (B2C)** | 정책자금 탐색 시간 90% 절감 + 이자 절감액 즉시 수치화 |
| **스마트기기 업체 (B2B)** | ROI 시뮬레이션과 연계한 서빙로봇·키오스크 솔루션 매칭 수수료 |
| **기관/지자체 (B2B)** | 서비스 내 누적 소상공인 데이터 기반 정책 효과 분석 API |
| **금융기관** | 신용보증기금, 소상공인시장진흥공단 정책 상품 중개 연계 |

**데이터 플라이휠**: 사용자가 늘수록 동종업계 통계 데이터가 풍부해지고, 이는 Stats Node의 비교 정확도와 서비스 가치를 높이는 선순환 구조를 만듭니다.
